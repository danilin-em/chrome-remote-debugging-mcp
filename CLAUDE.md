# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An MCP server (stdio transport, built on `FastMCP`) that controls an *already-running* Chrome over the Chrome DevTools Protocol (CDP). By default it does **not** launch Chrome — a browser must already be listening on the remote-debugging endpoint (`google-chrome --remote-debugging-port=9222 --user-data-dir=<dir>` — since Chrome 136 the port is not opened for the default profile, so a non-default `--user-data-dir` is mandatory). Currently a skeleton meant to be extended with more tools. The opt-in exception is `CHROME_LAUNCH` (see Conventions), which makes the server start a local Chrome itself.

## Commands

```bash
uv sync                         # venv + runtime + dev group (pytest, pytest-cov)

pytest -q                       # full suite; addopts enforce 100% branch coverage
pytest tests/test_server.py::test_ping_connected --no-cov   # single test — see gate note

python -m chrome_remote_debugging_mcp   # run server over stdio
uvx --from . chrome-remote-debugging-mcp

uv run python scripts/capture_ax_fixtures.py   # refresh tests/fixtures (needs live Chrome; see its docstring)
uv run python scripts/smoke_browse.py          # end-to-end check against a live Chrome
```

Tests need **no real Chrome and no network** — the CDP layer / websockets are monkeypatched (see `_stub` / `FakeBrowser` in `tests/test_server.py`, `FakeBrowserWS` in `tests/test_cdp.py`).

`pyproject.toml` bakes `--cov-branch --cov-fail-under=100` into pytest `addopts`, so **any partial run (one test or one file) reports a coverage failure and exits non-zero even when the tests themselves pass** — append `--no-cov` for those. The full `pytest` run must stay at 100%, so a new tool needs tests covering every branch (including its `{"error": ...}` paths). `__main__.py` is coverage-omitted (entry shim). CI (`.github/workflows/ci.yml`) reruns the suite on Python 3.10–3.13.

## Architecture

Five modules, layered so the I/O-free pieces (`cdp.py`, `ax.py`) stay testable
without a browser and the MCP-aware layer (`server.py`) stays thin:

- **`cdp.py`** — thin CDP client, zero MCP awareness. `Browser` holds **one persistent connection to Chrome's browser-level websocket**, opened lazily by the first `call(method, params, *, session_id=None, timeout=None)` and reopened by the next call after it dies (never retried on its own). Commands are multiplexed over it by `id`: a single reader task resolves each caller's future from the matching reply and drops events, except `Target.detachedFromTarget`. A tab is addressed as `Page(browser, target_id)`; `send(page, method, params)` runs a command in that tab's **flattened session** (`Target.attachToTarget {flatten: true}`), attached on first use and cached until `Target.detachedFromTarget` or the connection dies. The only HTTP request is `browser_ws_url` → `GET /json/version`, for the socket's address; `Browser` asks for it on every (re)connect, so a respawned tunnel or relaunched Chrome is picked up. Raises `CDPError` on a CDP-level error; `CDPTimeout` when a reply exceeds `SEND_TIMEOUT` (30 s; per-call `timeout=` override; the connection stays open), `CDPDisconnected` when the connection closes before the reply, and `TargetDetached` when the tab's session goes away first — all three deliberately *not* `CDPError` subclasses, so `actions.py`'s CDPError→stale-ref conversion never misreads a stalled or dropped transport (e.g. a half-dead ssh tunnel) or a closed tab as a stale ref.
- **`ax.py`** — accessibility tree → view lines. **Pure: no I/O, no `cdp` import.** Holds every rendering rule (role tables, filtering, block grouping, indentation). Because it is pure it is tested directly against captured trees in `tests/fixtures/`, with no Chrome and no mocks. When it needs data the tree lacks — DOM attributes for elements Chrome could not name — it does not fetch: `unnamed_backend_ids(nodes)` reports what is needed and the caller passes it back via `render_nodes(..., attrs=...)`.
- **`actions.py`** — one page action → CDP frames. Uses real `Input.*` events resolved through `DOM.getBoxModel`, never synthetic JS events, so `isTrusted` is true — with one documented exception: `select` sets a `<select>`'s value with `Runtime.callFunctionOn` and dispatches `input`/`change` itself, because a native option popup is browser chrome, not page content, and cannot be driven by a click. Handlers that convert a CDP failure into a stale-ref message catch `cdp.CDPError` only, never bare `Exception`, so a transport failure (e.g. the websocket itself dying) is reported honestly instead of being misdiagnosed as a stale ref. Raises `ActionError` with agent-readable text.
- **`browse.py`** — per-tab ref registry (`REGISTRY[tab_id] = _Snapshot(refs, main_frame_id, loader_id)`, where `refs` is `{ref: (frame_id, backend_node_id)}`), snapshot assembly across frames guarded by a per-tab `asyncio.Lock`, and batch execution that stops at the first failure. Registry entries (and their locks, in `_LOCKS`) are pruned only by `browse.forget`, which the `close_tab` tool calls; a tab closed any other way (by the user, by the page) leaves its entry behind.
- **`server.py`** — `FastMCP` instance + all `@mcp.tool()` functions + `main()`, plus the process-wide `cdp.Browser` (`_BROWSER`, created by the first `_browser()`; its address provider reads `CDP_URL` at connect time). Tabs are listed, opened and closed with `Target.getTargets` / `Target.createTarget` / `Target.closeTarget` over that connection. Imports the browse module as `from . import browse as browse_engine`, because the tool function `browse` would otherwise shadow the module name — never write `import browse` when describing this layout.

Three invariants to preserve when adding tools:

1. **Tools never raise — they return dicts.** On any failure return `{"error": "..."}`. Every existing tool wraps its CDP calls in try/except and converts exceptions (including `cdp.CDPError`) to an `{"error": ...}` payload. This is the contract MCP clients rely on.
2. **Target resolution goes through `_resolve_target(tab_id)`.** It filters to `type == "page"` targets and raises `_TargetError` (a human-readable message) when Chrome is unreachable / unknown id. There is no "default tab": only `navigate` and `browse` accept `tab_id=None`, and they route it through `_target_or_new`, which opens a fresh tab via `Target.createTarget {url: "about:blank"}`, then `Page.navigate`. Every other tab-scoped tool takes a required `tab_id`. Callers catch `_TargetError` and return it as `{"error": ...}`.
3. **`ax.py` stays pure.** No imports from `cdp`, no `async`. This is what makes the rendering rules testable against fixtures; adding I/O there would force mocks into every rule test.

`cdp_command` is the raw escape hatch: it forwards any `method` + `params` to `cdp.send`, i.e. into the tab's **persistent session**, so `objectId`/`nodeId` values and domain state survive between calls while the tab is open and the connection lives. It deliberately does not filter methods, but events are never delivered, so a command that waits on the client to answer an event hangs the tab until it is undone or the tab is closed: `Fetch.enable` (undo: `Fetch.disable`), `Debugger.pause` (`Debugger.resume`), `Target.setAutoAttach {waitForDebuggerOnStart: true}` (`…{waitForDebuggerOnStart: false}`), `Page.setInterceptFileChooserDialog {enabled: true}` (`…{enabled: false}`). Its docstring says so. `Browser.*` and `Target.*` are not supported through it; their results are undefined.

**Refs are per-snapshot, by design.** Numbering follows tree order, so a DOM change earlier in the document shifts every later ref. `browse.snapshot` replaces the tab's registry wholesale, and staleness is detected per verb by whichever CDP getter that verb calls against the (possibly dead) backend id: `DOM.getBoxModel` via `resolve_box` for `click`, `type` (which clicks first) and `hover`; `DOM.scrollIntoViewIfNeeded` called directly for a bare scroll-by-ref; and `DOM.resolveNode` via `_call_on_node` for `select`, `check` and `uncheck` — whichever one runs, a dead node makes it fail with `cdp.CDPError`, caught and re-raised as an agent-readable stale-ref message. A closed tab (`cdp.TargetDetached`) or a dropped connection (`cdp.CDPDisconnected`) is not a `CDPError` and so never becomes a stale-ref message; it reaches the tool's `{"error": ...}` as itself. An interactive node with no `backendDOMNodeId` renders without a `#N` rather than consuming a ref number it could never resolve back through (see `_content_line` in `ax.py`) — this is what keeps the printed refs and the ref map in lockstep by construction; do not "fix" it into always numbering. Do not add ref stability without re-reading D4 in `.superpowers/docs/specs/2026-09-03-browse-tools-design.md`.

**Actions can only reach the main frame.** Every action is dispatched in the page target's own session, which addresses only the main frame's renderer — a node from a same- or cross-origin child frame lives in a different coordinate space (and, cross-origin, a different renderer process) this tool cannot reach. `browse._resolve` therefore refuses a ref whose `frame_id` differs from the snapshot's `main_frame_id` with an honest "not the main frame" error instead of forwarding it to fail later as a misleading stale ref. Do not attempt coordinate offsetting or a per-frame socket to "fix" this — it is a documented limitation (see the design document's Out of scope section), not a bug.

**A snapshot's refs are only valid for that document, not just that array shape.** `browse.snapshot` stamps each `_Snapshot` with the main frame's `Page.Frame.loaderId`. `backendNodeId` numbering is monotonic and unique only within one renderer process; a cross-process navigation restarts it from 1, so without this stamp an old ref could resolve to a live, unrelated node in the new document instead of failing as stale. `run_actions` re-fetches the current loaderId before running any action in a batch and refuses the whole batch if it no longer matches.

**Snapshot assembly is serialised per tab.** `browse.snapshot` runs its whole body under `_lock_for(tab_id)`, an `asyncio.Lock` created lazily per tab id. Without it, two concurrent `browse`/`browse_view` calls on the same tab could finish in either order and the one that lost the race would return a view whose refs no longer match what `REGISTRY[tab_id]` ends up holding. The lock is per-tab, never global — do not collapse `_LOCKS` into a single lock; that would serialise unrelated tabs against each other for no reason.

**`wait_for` refuses `text` and `ref_gone` together.** `actions.wait_for` would silently prefer `text` if both were passed through; `browse._perform` rejects the combination up front with an `ActionError` instead of letting one condition win unannounced. Do not remove this guard to simplify the call site — it is the only thing standing between "ambiguous input" and "silently wrong behavior".

**The accessibility tree does not include child frames.** The main frame's `Iframe` node has empty `childIds`. `browse.snapshot` therefore walks `Page.getFrameTree` and calls `Accessibility.getFullAXTree({frameId})` once per frame. In the assembled view, every frame after the first is marked with a `frame <id>` line showing only the **first 8 characters** of the frame id (a display truncation only — the registry keys on the full id, never the truncated one).

**`Accessibility.*` and `DOM.*` getters need no `enable` call**; `enable` gates a domain's event stream, not its commands. Every command for a tab runs in that tab's one cached session, so state a command creates (an `objectId`, a `nodeId`, an enabled domain) outlives it until the tab detaches or the connection dies — which is why `actions.py` releases the objects it resolves (`Runtime.releaseObject`) rather than leaking them into a long-lived session.

## Conventions

- Config comes from env vars read once at import in `server.py`: `CDP_URL` (default `http://localhost:9222`), the optional SSH tunnel pair `SSH_PROXY_TO` / `SSH_PROXY_PORT`, and the optional `CHROME_LAUNCH` flag.
- **Optional debug log** (`debuglog.py`): `MCP_DEBUG_LOG` (read once at import) wraps every registered tool so each call's arguments, result (or exception) and duration are appended to a file — `1`/`true`/`yes`/`on` → `/tmp/chrome-remote-debugging-mcp.log`, any other non-falsy value is the path. Unset/falsy leaves the tools unwrapped. `debuglog.install(mcp)` runs at the bottom of `server.py`, after every `@mcp.tool()` is registered; it is intended to stay committed.
- **Optional SSH tunnel** (`tunnel.py`): when `SSH_PROXY_TO` (e.g. `user@remote`) is set, `main()` opens `ssh -N -L 127.0.0.1:<local>:<host>:<port> <target>` to the `CDP_URL` endpoint (now interpreted as the *remote-side* address), then rewrites the module-global `CDP_URL` to the forwarded `http://127.0.0.1:<local>`. `SSH_PROXY_PORT` fixes the local port (else auto). A local forward — not SOCKS5 — is required: Chrome's debugging port refuses any `Host` header that is not `localhost`/`127.0.0.1`. Tools are unchanged because the browser connection reads `CDP_URL` each time it (re)connects. ssh dies on its own when the connection drops (`ServerAlive*`); `server._ensure_tunnel()` — called from `_page_targets`, `_open_target` and `ping`, i.e. before any CDP traffic — respawns it on the **same** local port via `SshLocalForwardTunnel.ensure_alive()` (in a worker thread, under a lock), so `CDP_URL` stays valid. A failed respawn surfaces as the tool's `{"error": ...}`. A `stop()`-ed tunnel is never resurrected.
- **Optional Chrome auto-launch** (`launcher.py`): `CHROME_LAUNCH` (`1`/`true`/`yes`/`on`) makes the server start its own local Chrome instead of connecting to `CDP_URL`. It is mutually exclusive with `CDP_URL` and `SSH_PROXY_TO` — `main()` raises `SystemExit` when combined ("set" means present in the environment, tracked as `_CDP_URL_SET`). `main()` only creates the `ChromeLauncher`; the launch is **lazy**: `server._ensure_chrome()` — called right after `_ensure_tunnel()` in `_page_targets`, `_open_target` and `ping` — runs `ChromeLauncher.ensure_alive()` in a worker thread (under a lock) and rewrites `CDP_URL` on **every** call, because a relaunch lands on a new port. Chrome is started with `--remote-debugging-port=0` in the persistent profile `~/.cache/chrome-remote-debugging-mcp/chrome-profile`, and the port is read from `<profile>/DevToolsActivePort`. If a Chrome already serves that profile (another MCP session), the launcher attaches instead of launching; ownership is `_proc is not None`, and `stop()` (on server exit) closes Chrome only when this instance launched it — never break that, or one session would kill another's browser. Chrome's stdout goes to `DEVNULL` because stdout is the MCP channel. Launching over SSH is a planned second stage, not supported yet.
- `cdp._ids` is a module-level `itertools.count` for command/response correlation; tests monkeypatch it to reset for deterministic frame-id assertions — keep it module-level.
- All I/O is `async`; tools are `async def` and tests drive them with `asyncio.run(_fn(tool)())`. `_fn` unwraps the tool whether `@mcp.tool()` returns the raw function or a wrapper.
